# TokenBaseball v0.2 — 구현 및 검증 결과

작성일: 2026-09-17

## 구현 범위

사용자가 확정한 변경 사항을 구현했다. 첫 실행에 무작위 이름의 루키 9명을 지급하고, 별도 볼 재화·상점을 제거했다. 누적 50M 토큰마다 뽑기 카드 1장을 받으며 등급 확률은 루키 75%·올스타 20%·레전드 5%다. 선수 포지션은 고정이고, 선수단은 상단 야구장 배치와 하단 목록으로 구성된다. macOS 상태바에는 오늘 사용한 토큰을 표시한다.

## 자동 테스트와 빌드

최종 핵심 코드의 `swift test`에서 **70개 테스트가 통과**했다. 상태바와 선수단 화면을 포함한 앱 타깃과 release 앱을 빌드했고, `codesign --verify --deep --strict` 검증도 통과했다. 실행 환경은 Apple Silicon, macOS 26.6.2, Xcode 26.5 / Swift 6.3.2다. 최소 배포 대상은 macOS 14이며 구형 OS 실기기는 검증하지 않았다.

| 테스트 묶음 | 개수 | 확인 내용 |
| --- | --- | --- |
| Codex 사용량 | 23 | 세션 ID·누적 증가분·중복 기록·자정·시간대·누락 날짜·캐시 무효화·취소 |
| Claude Code 사용량 | 22 | 메시지 중복·스트리밍 증가·캐시 토큰·날짜 보정·파일 캐시·취소 |
| 기본 선수·저장·마이그레이션 | 12 | 기본 9명과 이름 유지, v1 백업, 카드 출처·뽑기 횟수 대조, 손상·오래된 저장 거부 |
| 토큰 보상·뽑기 | 5 | 50M 경계·중복 방지·75/20/5 경계·카드 부족·저장 실패·오버플로 |
| 선수단 | 2 | 고정 포지션, 교체·제외, 저장 실패 |
| 꾸미기 | 3 | 이름·사진·초기화, 등급·포지션 유지, 저장 실패 |
| 표시·날짜 키 | 3 | K·M·B 경계, 현지 자정, 불교력·일본력 설정에서도 동일한 날짜 키 |

날짜별 기록은 재조회 결과로 보정하고 누적량은 출처별 최대 인정량을 유지한다. 시간대 변경이나 과거 기록의 날짜 보정 때문에 토큰과 뽑기 카드가 다시 지급되지 않는 것을 검증했다.

## 앱 상태 통합 검증

프로덕션 `AppModel.swift`와 코어 코드를 사용한 임시 실행형 검증 도구에서 합성 Codex·Claude 기록을 읽었다. 실제 사용 기록·게임 저장 위치와 분리했다.

- 시작 시 루키 9명과 9개 포지션 자동 배치.
- 앱 초기화에 따른 자동 집계: 누적 225M, 오늘 50M, 뽑기 카드 4장.
- 카드 1장 열기: 보유 선수 10명, 남은 뽑기 카드 3장, 누적 225M 유지.
- 다른 포지션 배치 요청 거부와 기존 상태 보존.
- 다시 불러오기·새 AppModel 생성·자동 재집계 후 기존 선수와 뽑기 카드 수 유지.

이 검증은 앱 상태와 저장 흐름에 대한 검증이며 화면 조작 검증은 아니다. 임시 도구와 합성 저장 데이터는 저장소에 포함하지 않았다.

## 실제 앱 실행과 화면 검수 제한

별도 식별자와 테스트 저장 폴더를 사용하는 개발용 앱을 실행했다. 생성된 저장 파일에서 루키 9명·9개 포지션·누적 0 토큰을 확인했다.

이후 화면 조작 도구가 `timeoutReached`, `Sky Computer Use native pipe closed before response` 오류로 연결을 종료했다. 재연결·도구 세션 초기화 후에도 복구되지 않았다. 따라서 **v0.2 야구장 배치의 시각 검수, 상태바 실제 표시, 클릭을 통한 뽑기·교체·창 재열기는 미완료**다. 기능 목록의 체크 표시는 구현 완료이며, 이 수동 검수까지 완료했다는 뜻은 아니다.

## 실제 사용 기록 읽기 확인

- Codex 로컬 기록 1,395개에서 최초 읽기 약 44.36초, 같은 가져오기 객체의 재조회 약 0.17초를 확인했다. 재조회 시 변경되지 않은 파일은 다시 파싱하지 않았다.
- 실제 기록을 읽는 검사는 읽기 전용이었다. 대화 본문·세션 식별자·실제 토큰 합계를 저장소에 복사하지 않았다.
- Claude 기본 폴더에는 실제 기록이 없어 빈 결과를 정상 처리했다. Claude의 동작은 합성 로그로 검증했으며 실제 세션 기록 확인은 남아 있다.

## 후속 확인

화면 조작 도구 복구 후 야구장·상태바·창 재열기를 수동 확인한다. 경기 시뮬레이션·육성·합성·거래·대결, 외부 배포용 서명·공증과 자동 업데이트는 이번 변경 범위에 포함하지 않는다.

## 선수단 초상화 배치 수정 — ROS-08

- 야구장 카드의 표시 순서를 초상화 → 이름 → 포지션으로 변경했다. 사진 미등록 선수도 사람 아이콘 대신 기본 초상화를 사용한다.
- 기본 초상화 9종을 앱에 포함했다. 등록 사진을 우선하고 상단 카드·하단 목록에서 동일한 얼굴을 표시한다.
- 정확한 프로덕션 카드 컴포넌트를 임시 SwiftUI 렌더 도구로 검증했다. 9개 기본 얼굴의 크롭, 128×140 카드의 텍스트 배치, 합성 등록 사진 우선 표시, 빈자리 표시를 확인했다.
- 이미지 이름만으로 읽을 때 렌더가 비어 보이는 문제를 명시적인 번들 URL 기반 이미지 로딩으로 수정한 후 다시 렌더했다.
- release 빌드와 strict 서명 검증을 통과했다. 다른 위치로 복사한 앱에서도 내장 PNG를 읽고 디코딩하는 것을 확인했다.
- 이번 수정의 검증은 카드 렌더링과 패키지 검증이다. 전체 창의 클릭·교체 조작 검수는 포함하지 않았다. 토큰·뽑기·저장 로직은 변경하지 않아 기존 코어 테스트를 반복 실행하지 않았다.
- 생성 방식과 프롬프트는 [초상화 자산 기록](선수-초상화-자산.md)에 남겼다.

## 경기장 초상화 크기 조정 — ROS-08

- 상단 초상화 최대 크기를 84pt에서 48pt로, 선수 배치 영역을 128×140pt에서 88×96pt로 축소했다. 하단 목록의 초상화는 유지했다.
- 경기장 높이를 640pt에서 520pt로 줄이고 최대 너비는 720pt로 제한했다. 외야수·내야수·투수·포수의 상대 위치와 다이아몬드 비율을 함께 조정했다.
- 라이브 화면과 검증 도구가 동일한 `BaseballField`를 사용하도록 분리했다. 카드 단독 검증 대신 400·520·720pt 전체 경기장을 밝은·어두운 모드로 렌더했다.
- 9명 초상화와 기본 이름·포지션 표시, 좌우 균형, 카드 간 겹침 및 가장자리 잘림을 확인했다. 유격수·2루수와 투수 사이 간격도 추가로 확보했다.
- release 빌드와 strict 서명 검증을 통과했다. 변경 범위는 화면 배치이며 토큰·뽑기·저장 로직은 수정하지 않았다.

## 원본 이미지가 경기장을 덮는 오류 수정 — ROS-09

### 원인과 이전 검증의 한계

사용자의 실제 실행 창에서 큰 세로 이미지 조각이 경기장을 덮는 현상을 확인했다. `NSHostingView`에서 동일한 Menu를 재현하자 88×96pt 슬롯이 `SwiftUIPopupButton` 93×1254, 내부 `NSButtonImageView` 1254×1254로 팽창했다. macOS Menu가 사진의 원본 크기를 사용하며 SwiftUI frame·clip을 무시하는 문제였다.

이전 카드·필드 ImageRenderer 검증에는 실제 메뉴 버튼이 포함되지 않아 이를 발견하지 못했다. 동일 코드를 일반 Button으로 바꾼 대조 실험에서는 지정한 영역을 유지했다.

### 수정

- 상단 Menu를 일반 Button + 선수 선택 popover로 전환했다. 포지션별 교체·제외 동작은 유지했다.
- atlas와 사용자 사진을 실제 정사각형 비트맵으로 잘라 축소한다. 원본 이미지가 레이아웃에 노출되지 않도록 이미지 고유 크기도 제한했다.
- 상단 초상화는 32pt, 클릭 영역은 최대 76×72pt로 줄이고 큰 카드 배경을 제거했다. 초상화 아래 이름·포지션은 유지했다.

### 확인

실제 RosterView·AppModel·Components·BaseballField·RosterPlayerPortrait 소스를 그대로 사용한 NSHostingView로 540·784pt 너비, 밝은·어두운 화면 4개 조합을 검증했다. 격리된 합성 데이터에 2400×1600 사용자 사진을 추가했고, 이 사진도 32pt 중앙 크롭으로 표시되는 것을 확인했다. 포지션별 native view 9개는 모두 최대 76×72pt였고, 비정상적으로 큰 이미지 뷰는 없었다. 기본 초상화·등록 사진·이름·포지션·경기장·하단 목록을 확인했다.

release 빌드와 strict 서명 검증도 통과했다. 실제 앱의 수정 전 오류 화면까지는 컴퓨터 조작 도구로 확인했으나, 앱 재시작 중 `Sky Computer Use native pipe closed before response`가 발생해 수정 후 창과 팝업 클릭은 같은 도구로 재확인하지 못했다. 최종 시각 검증은 위의 실제 native view 렌더에 기반한다. 열려 있는 구버전 프로세스는 완전히 종료한 후 새 앱을 실행해야 한다.
