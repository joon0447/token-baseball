# TokenBaseball v0.1 — 구현 및 검증 결과

작성일: 2026-09-17

## 구현 범위

기능 구현 목록의 43개 항목을 개발용 초기 정책으로 구현했다. Codex와 Claude Code의 로컬 기록을 수동 갱신하고, 재화를 받아 카드를 구매·꾸미고 선수단에 배치할 수 있다.

| 기능 | 주요 코드 |
| --- | --- |
| 앱 실행·탐색·오류 표시 | `Sources/TokenBaseball/TokenBaseballApp.swift` |
| 화면 상태·사용량 가져오기·취소 | `Sources/TokenBaseball/AppModel.swift` |
| 홈·연동 설정 | `Sources/TokenBaseball/HomeSettingsViews.swift` |
| 상점·보유 카드·상세·선수단 | `Sources/TokenBaseball/*View.swift` |
| 카드·재화·선수단 모델 | `Sources/TokenBaseballCore/Models.swift` |
| 원자 저장·정수 검증·동시 실행 충돌 방지 | `Sources/TokenBaseballCore/Persistence.swift` |
| 토큰 적립·구매·배치·꾸미기 | `Sources/TokenBaseballCore/GameStore*.swift` |
| Codex·Claude Code 사용량 | `Sources/TokenBaseballCore/*UsageImporter.swift` |

## 자동 검증

`swift test`에서 **59개 테스트가 통과**했다. 실행 환경은 Apple Silicon, macOS 26.6.2, Xcode 26.5 / Swift 6.3.2다. 앱의 최소 배포 대상은 macOS 14이며 구형 OS 실기기 테스트는 별도다.

| 테스트 묶음 | 개수 | 확인 내용 |
| --- | --- | --- |
| Codex 사용량 | 18 | 안정적 세션 ID·구형 ID, 중복·누적량, 숫자 오류, 부분 기록, 취소 |
| Claude Code 사용량 | 16 | 메시지 중복·스트리밍 증가, 캐시 토큰, 부분 기록, 취소 |
| 저장 | 15 | 재로딩, 원자 저장, 손상·미지원 버전 보존, 잘못된 숫자, 동시·오래된 저장 거부 |
| 재화·구매 | 5 | 잔여 토큰, 중복 지급, 잔액 부족, 중복 구매, 저장 실패·오버플로 |
| 선수단 | 2 | 중복 배치, 교체·제외 후 카드 보존, 저장 실패 |
| 꾸미기 | 3 | 이름 검증, 사진 저장·초기화, 등급·배치 유지, 저장 실패 |

각 기능 커밋에서 관련 테스트 또는 빌드를 통과시켰다. UI와 저장 로직은 같은 기능 ID를 기준으로 연결했다.

## 실제 기록 확인

- Codex 기본 폴더에서 약 2.07GiB, 1,394개 JSONL을 읽는 데 성공했다. 활성·보관·복사 기록은 안정적 세션 ID별로 병합했다.
- 실제 기록에서 재개 시 `id`가 달라지는 사례를 확인하고 `session_id` 우선 처리로 수정했다.
- Claude Code 기본 폴더는 현재 기록이 없는 상태로 정상 처리됐다. 실제 Claude 세션이 생겼을 때의 현장 확인은 남아 있으며, 포맷별 동작은 합성 테스트로 검증했다.
- 실제 기록 검사는 읽기 전용으로 진행했다. 게임 잔액에 지급하거나 대화·식별자를 저장소에 복사하지 않았다.

## 실제 화면 확인

실제 저장 위치와 분리한 합성 데이터로 개발용 앱을 실행했다.

- 43볼 상태에서 루키 카드 10볼 구매 → 잔액 33볼, 카드 1장 지급, 같은 카드 구매 버튼 비활성화.
- 보유 카드 상세에서 이름 저장 → 목록·선수단에 변경한 이름 표시.
- 카드 상세에서 투수 배치 → 선수단 1/9 표시, 다른 자리에서 같은 카드 등록 제한.
- PNG 파일 선택 → 미리보기 → 사진 적용 → 선수단 사진 반영.
- 공백 이름 저장 거부와 기존 이름 보존.
- 저장 파일에 토큰·재화·카드·배치·이름·PNG 데이터가 함께 기록된 것을 확인.

이후 컴퓨터 조작 도구의 연결이 종료되어, 최종 수정본의 취소 버튼·오류 시트 해제와 앱 재실행을 화면에서 다시 확인하지 못했다. 취소 처리와 저장 복원 자체는 자동 테스트로 통과했다. 해당 화면 재검증은 후속 확인 항목이다.

## 남은 제품 결정

재화 환산 비율, 카드 가격·판매 구성, 포지션 규칙, 이름·이미지 제한은 [개발 규칙](개발-규칙.md)의 초기값이다. 최종 정책으로 확정되면 관련 모델과 기존 데이터 마이그레이션을 함께 수정해야 한다.

경기·육성·합성·거래·대결은 이번 범위에 포함하지 않았다. 배포용 서명·공증, 자동 업데이트도 후속 작업이다.
