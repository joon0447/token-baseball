# Codex 로컬 사용량 가져오기

이 어댑터는 사용자가 선택한 폴더의 JSONL 기록을 읽는다. 네트워크, API 키, 계정 인증은 사용하지 않는다. Codex의 공개된 안정적 사용량 API가 아니므로, 기록 형식이 바뀌면 어댑터 수정이 필요할 수 있다.

## 읽는 값

2026-09-17 로컬 Codex 세션 파일 1,394개의 메타데이터 구조를 확인했다. 실제 대화, 경로, 세션 식별자, 토큰 수 값은 문서나 테스트에 복사하지 않았다. 테스트 데이터는 모두 합성 데이터다.

- `type == "session_meta"`인 기록의 `payload.session_id`: 데스크톱 기록의 안정적인 세션 식별자. 이 키가 없는 구형 CLI 포맷에서는 `payload.id`를 사용한다.
- `type == "event_msg"`이고 `payload.type == "token_count"`인 기록의 `payload.info.total_token_usage.total_tokens`: 세션 누적 토큰 수

결과 식별자는 `codex:<세션 식별자>`다. 파일명으로 세션을 추정하지 않는다. 같은 세션이 활성·보관·복사 파일에 중복되어 있어도 가장 큰 누적값 하나만 반환한다. 같은 파일의 여러 누적값을 더하지 않는다. 입력·출력·캐시·추론 토큰 필드를 따로 더하지 않는다.

## 날짜별 사용량

`UsageSnapshot.dailyTokens`는 `yyyy-MM-dd` 키와 해당 날짜의 토큰 수를 가진다. 날짜는 `token_count` 레코드 최상위의 ISO 8601 `timestamp`를 읽어서 계산한다. 가져온 날짜나 파일 수정 시각으로 대체하지 않는다.

같은 세션의 모든 파일을 합친 뒤 timestamp 순으로 정렬한다. 첫 유효 누적값과 이후 이전 최고 누적값을 초과한 양만 해당 레코드 날짜에 배분한다. 같은 timestamp의 계수는 최댓값 하나로 합치며, 복사·재개·반복·감소된 계수는 토큰을 다시 더하지 않는다. 자정을 지나는 세션도 각 증가분이 관측된 날짜에 나뉜다.

timestamp가 없거나 파싱할 수 없는 계수는 누적 총량에만 포함한다. 그중 가장 큰 누적값을 날짜 미귀속 기준값으로 두고, timestamp가 있는 기록 중 이 값을 초과한 증가분만 날짜에 배분한다. 따라서 불완전한 기록의 날짜별 합계는 누적 총량보다 작을 수 있다. 날짜를 모르는 과거 사용량이 오늘 사용량에 들어가지 않도록 보수적으로 처리한다.

`init(calendar: Calendar = .autoupdatingCurrent)`로 시간대를 지정할 수 있다. 날짜 키는 해당 시간대의 그레고리력 날짜이며, 기본값은 macOS 시간대 변경을 따른다. 테스트에서는 고정된 시간대의 달력을 주입한다.

실제 기록 중 97개 파일은 재개된 메타데이터의 `id`가 변경되었으나 `session_id`는 일정했다. 따라서 `session_id`가 있는 포맷에서 `id`를 세션 식별자로 취급하지 않는다. `session_id`가 명시되어 있으나 값이 잘못되었다면 `id`로 우회하지 않고 오류로 처리한다.

전체 JSON 줄은 메모리에서 구문 분석하지만, 대화 내용은 의미적으로 처리하거나 저장·표시·전송하지 않는다. 결과에는 세션 식별자와 토큰 수만 포함한다. 원본 파일을 수정하지 않는다.

## 폴더 범위

- 선택 폴더에 `sessions` 또는 `archived_sessions`가 있으면 해당 하위 폴더만 재귀적으로 탐색한다.
- `.codex` 폴더에는 위 두 하위 폴더가 없어도 다른 파일을 대신 읽지 않는다. 예를 들어 `history.jsonl`은 대상이 아니다.
- 사용자가 세션의 날짜별 하위 폴더를 직접 선택할 수도 있다.
- 숨김 파일·패키지 내부·심볼릭 링크는 건너뛰고 일반 `.jsonl` 파일만 읽는다.
- 존재하는 폴더가 비어 있으면 빈 결과를 반환한다. 선택한 폴더가 없으면 오류를 반환한다.

## 검증과 원자성

- 토큰 수는 0 이상 `Int64.max` 이하의 JSON 정수여야 한다. 불리언, 문자열, 소수, 지수 표기, 음수, 범위 초과는 거부한다.
- 사용량이 있는 파일은 유효한 `session_meta.payload.session_id` 또는 구형 포맷의 `payload.id`를 포함해야 한다. 파일 내 서로 다른 안정적 세션 식별자는 오류다.
- `token_count.info == null`은 아직 사용량이 없는 상태로 보고 건너뛴다. 나머지 사용량 필드 누락이나 잘못된 값은 오류다.
- 완성된 줄이 잘못되었으면 호출 전체가 오류로 끝난다. 이전 파일에서 읽은 부분 결과를 반환하지 않는다.
- 파일 끝에 줄바꿈 없이 남은 줄은 유효한 JSON이면 읽는다. 구문 분석이 불가능한 경우에만 아직 기록 중인 마지막 줄로 보고 무시한다. 따라서 줄바꿈 없는 잘못된 최종 JSON도 다음 읽기까지 무시될 수 있다. 유효한 JSON에 잘못된 토큰 값이 있으면 줄바꿈 유무와 관계없이 오류다.

## 자원 한도

64 KiB씩 스트리밍한다. 한 줄 최대 16 MiB, 호출당 실제 읽기 최대 8 GiB, JSONL 파일 최대 10,000개, 디렉터리 항목 최대 100,000개다. 한도를 넘으면 부분 결과 없이 오류를 반환한다. 더 작은 날짜별 폴더를 선택해 다시 가져올 수 있다. 시작 시점과 폴더·파일·청크마다 Swift Task 취소를 확인하여 사용자가 가져오기를 취소할 수 있게 한다.

## 자동 갱신 캐시

같은 importer 인스턴스를 재사용하면 변경되지 않은 파일은 다시 파싱하지 않는다. 캐시에는 세션 식별자·누적 계수·timestamp만 있고 원본 줄이나 대화는 없다. 경로·장치·inode·크기·나노초 단위 mtime/ctime·파일 모드를 비교하므로 같은 크기로 덮어쓰고 mtime을 복구해도 수정된 파일을 다시 읽는다. 읽기 권한도 매번 확인한다.

읽기 전후 파일 서명이 달라지면 해당 결과는 캐시에 저장하지 않아 다음 갱신에서 다시 읽는다. 없어진 파일은 이번 결과에서 제외하며 캐시에서도 제거한다. 파싱에 실패하거나 취소된 파일은 캐시하지 않는다. 캐시 딕셔너리는 잠금으로 보호하여 `Task.detached`에서 같은 Sendable 인스턴스를 사용할 수 있다. 캐시된 날짜는 절대 시각인 `Date`이므로 시간대별 날짜 배분은 매번 다시 계산한다. 첫 읽기는 전체 파일을 읽고, 이후 갱신은 변경된 파일만 읽는다.

앱의 저장 계층은 이 결과를 기존 세션별 누적값과 비교해 새로 증가한 양만 반영해야 한다. 이 어댑터 자체는 재화 지급이나 저장 상태를 변경하지 않는다.
