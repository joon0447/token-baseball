# 개발 규칙과 초기 정책

## 커밋 규칙

사용자가 선택한 Conventional Commits와 한국어 설명을 사용한다.

```text
feat(app): macOS 앱 실행과 화면 탐색 추가
fix(usage): 같은 사용 기록의 중복 집계 수정
test(store): 저장 실패 시 잔액 유지 검증
docs(plan): 구현 완료 항목과 검증 결과 갱신
```

- 형식: `type(scope): 한국어 설명`.
- `feat`, `fix`, `test`, `docs`, `refactor`, `chore`를 작업 성격에 맞게 사용한다.
- 기능 단위로 커밋한다. 커밋 본문에 구현 목록 ID와 검증 결과를 기록한다.
- 빌드 산출물, 개인 사용 기록, 선수 사진, 비밀 값은 커밋하지 않는다.

## 확정된 개발 방향

- 사용자가 지정한 프로젝트 폴더와 Git 원격 저장소를 사용한다.
- 사용자가 선택한 **Codex와 Claude Code 두 서비스의 로컬 사용 기록**을 지원한다.
- 구현 기술 선택: SwiftUI, Swift Package Manager, macOS 14 이상.
- 데이터는 로컬에 저장하고, 읽은 AI 대화 본문이나 도구 출력은 앱 데이터에 저장하지 않는다.
- 시스템 기본 탐색·목록·폼·파일 선택기를 사용한다. 별도 브랜드 시각 디자인은 이번 기능 구현과 분리한다.

## 개발용 초기 정책 — 사용자 확정 전 변경 가능

다음 값은 실제 흐름을 실행하고 검증하기 위한 초기값이다. 제품 정책으로 최종 확정된 값이 아니다.

| 항목 | 초기값 |
| --- | --- |
| 재화 | 볼 |
| 환산 | 누적 인정 토큰 1,000개당 1볼, 나머지 토큰은 다음 지급에 합산 |
| 카드 등급·가격 | 루키 10볼, 올스타 30볼, 레전드 100볼 |
| 상점 | 가상 선수 27명 고정, 카드 직접 구매, 동일 판매 카드 중복 구매 금지 |
| 선수단 | 수비 9자리, 카드 포지션과 다른 자리에도 배치 가능, 같은 보유 카드 중복 배치 금지 |
| 이름 | 앞뒤 공백 제거 후 1~30자 |
| 사진 | PNG/JPEG, 원본 최대 10MB, 미리보기 후 적용, 앱 내부에 축소 PNG 보관 |
| 이름·사진 변경 범위 | 선택한 보유 카드만 변경 |
| 사용량 반영 | 사용자가 폴더를 선택한 뒤 ‘사용량 반영’을 눌러 갱신 |
| 과거 기록 | 선택한 폴더에서 읽을 수 있는 과거 기록부터 누적 인정 |

환산 비율 변경에 따른 과거 재화 재계산은 현재 범위에 포함하지 않는다. 실제 환산·카드 가격은 코드의 정책 상수에서 관리한다.

## 사용량 범위

- Codex: 세션 누적 `total_tokens` 최댓값. 입력·출력 합계에 이미 포함된 캐시·추론 토큰은 중복 가산하지 않는다.
- Claude Code: 메시지별 입력·출력·캐시 생성·캐시 읽기 토큰을 합산한다. 같은 메시지의 반복 기록은 각 수치의 최댓값으로 병합한다.
- 서비스별 기록 식별값을 분리해 중복 지급을 방지한다.
- 두 서비스 중 하나라도 읽기 실패하면 해당 반영 작업 전체를 저장하지 않고 기존 잔액을 유지한다.
- 로컬 기록 파일은 안정적인 공개 API가 아니므로 서비스 버전 변경 시 어댑터 수정이 필요할 수 있다.
