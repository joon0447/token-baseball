# 개발 규칙과 운영 정책

## 커밋

- Conventional Commits + 한국어 설명: `feat(draw): 토큰 사용량에 따른 선수 뽑기 추가`.
- 기능 단위로 커밋하며 본문에 기능 ID와 검증 결과를 남긴다.
- 실제 AI 기록·개인 사진·비밀 값·빌드 산출물은 커밋하지 않는다.

## 기술

- SwiftUI · Swift Package Manager · macOS 14 이상.
- UI는 macOS 기본 컴포넌트·시스템 색상을 사용한다. 선수단 필드는 수비 포지션의 공간 관계를 나타낸다.
- JSON 저장은 원자적으로 수행하고, 동시 실행의 오래된 저장은 거부한다.
- v0.1 → v0.2 전환 시 원본 `state.json.v1.backup`을 보존한다.

## 사용자 확정 정책

| 항목 | 정책 |
| --- | --- |
| AI 서비스 | Codex + Claude Code 로컬 사용 기록 |
| 재화 표시 | 별도 ‘볼’ 없음, 토큰 수 K·M·B 표시 |
| 기본 선수 | 최초에 루키 9명, 포지션별 1명 자동 배치, 이름 무작위 |
| 뽑기 카드 지급 | 누적 50M 토큰마다 1장 |
| 등급 확률 | 루키 75% / 올스타 20% / 레전드 5% |
| 카드 획득 | 상점 없음, 뽑기 카드 1장당 선수 1명 |
| 포지션 | 획득 시 고정, 편집·다른 포지션 배치 불가 |
| 선수단 화면 | 상단 야구장 카드: 초상화 → 이름 → 포지션, 하단 목록 유지 |
| 상태바 | 오늘 사용한 토큰 수 표시 |

## 구현 세부 정책

- 무작위 포지션은 9개 중 동일 확률, 이름은 가상 이름 목록에서 무작위로 선택한다.
- 카드 열기는 누적 토큰을 차감하지 않는다. 남은 뽑기 카드 = 누적 지급 수 − 사용한 카드 수다.
- 이름은 앞뒤 공백 제거 후 1~30자, 사진은 PNG/JPEG 원본 최대 10MB이며 축소 PNG를 내부 보관한다.
- 날짜가 확인되는 사용 기록만 오늘 집계에 포함한다. 일별 배분을 다시 계산해도 누적 인정량을 중복 지급하지 않는다.
- 프로그램 실행 중 60초마다 갱신한다. 반복 갱신은 변경된 파일만 다시 읽는 메타데이터 캐시를 사용한다.
- 읽기 실패·취소·저장 실패 시 일부 결과만 반영하지 않는다.
- 사용자 기획 변경이 우선하며, 정책 상수 변경 시 기존 저장 파일의 호환성도 검토한다.

- 선수단은 등록 사진을 우선한다. 미등록 시 아이콘 대신 내장 기본 초상화를 사용하고 동일 선수의 기본 얼굴은 재실행·이름 변경에도 유지한다.

- 야구장 배치의 초상화는 74pt, 선수 영역은 최대 88×114pt로 유지한다. 외야·내야·투수·포수를 경기장 위치에 맞추고, 레이아웃 수정 시 단일 카드뿐 아니라 경기장 전체를 렌더링해 확인한다.

- 필드의 사진·이름 복합 레이블에는 native Menu를 사용하지 않는다. 일반 Button과 popover를 쓰고, 사진은 원본 이미지의 frame/clip에만 의존하지 않고 실제 썸네일로 변환한다. 전체 RosterView를 NSHostingView로 검증하여 native control의 크기도 확인한다.
